# 16 测试体系

> 分层策略、覆盖清单、运行方式与编写约定。对应任务「选项 1：测试体系兜底」（2026-10-18 建立）。

## 1. 分层策略

| 层 | 类型 | 工具 | 范围 | 运行条件 |
|----|------|------|------|----------|
| L1 | 单元测试 | JUnit 5 + Mockito | 纯逻辑工具类、状态机（mock mapper/依赖，无 Spring 上下文/DB） | 无需任何外部依赖 |
| L2 | 装配测试 | `@SpringBootTest` + H2 | 框架装配硬门禁（如 Flowable × Boot 4 引擎装配） | 无需外部中间件 |
| L3 | 端到端 | `smoke-e2e.py` / `verify_feign.py` | 网关路由、登录、安全基线（401/403/跨租户）、幂等、4 条跨模块 Feign 链路 | 需 11 服务 + 中间件就绪 |

**原则**：能放 L1 不放 L2（快、稳、无外部依赖）；L3 只覆盖「单测测不到」的集成面
（网关鉴权链、租户透传、Feign 直连），并作为部署后验收门禁。

## 3. 运行方式

```bash
# 单元 + 装配测试（全模块，无需运行中的服务）
bash scripts/test-all.sh

# 指定模块
bash scripts/test-all.sh --module hris-attendance

# 含端到端（需 11 服务 + 中间件就绪）
# DB_PASSWORD 必须由环境注入：不提供任何默认值，缺失时脚本 exit 2 明确报错
# （仓库内禁止硬编码数据库密码，与 JwtSecretGuard 门禁一致，见 docs/17 §3）
DB_PASSWORD=xxx bash scripts/test-all.sh --e2e
```

## 4. 编写约定

- **命名**：`XxxTest`（被测类 + Test）；`@DisplayName` 用中文描述行为与守卫
  （如「结束时间不晚于开始时间 → PARAM_INVALID」）。
- **L1 不引 Spring**：依赖用 Mockito mock（`@ExtendWith(MockitoExtension.class)`），
  断言异常走 `assertThrows(BizException.class)` + `getCode()` 比对 ErrorCode。
- **MyBatis-Plus mock 注意**：`BaseMapper` 的 `insert` / `updateById` 有单条与 `Collection`
  重载，`any()` 裸用会「引用不明确」，须写 `any(Entity.class)`。
- **void 方法桩异常**：被 mock 方法返回 void 时（如 `VectorStore.ensureCollection`）不能用
  `when(...).thenThrow(...)`（编译报「此处不允许使用 '空' 类型」），须用 `doThrow(...).when(mock).method(...)`。
- **静态上下文坑**：`AuthContextHolder` / `TraceContext` 是 ThreadLocal，测试须在
  `@AfterEach` 清理，且桩数据避免依赖类字段默认值（发现过 MilvusProperties 维度默认
  128 与 yml 1024 不一致，已对齐）。
- **单模块跑测试须带 `-am`**：否则 hris-common 不在 test classpath（`BaseEntity 找不到`）。
- **Maven 报错乱码**：Windows 下 Maven 输出为 GBK，`grep` 匹配不到中文错误；把日志重定向到文件后
  用 Python `decode('gb18030')` 解码可读。
- **门禁**：新增测试同样受 emoji/单文件 ≤300 行约束；测试是生产代码，按同一标准 review。
- **超长测试类要按「被测方法维度」拆文件**，而不是按断言数量拆：
  月结拆成 `MonthlyClosingServiceTest`（锁账状态机）/ `MonthlyClosingDetailTest`（结果集口径）/
  `MonthlyClosingAdjustmentTest`（红冲通道与列表）；令牌拆成 `TokenServiceTest`（签发解析）/
  `TokenServiceRevokeTest`（撤销与启动守卫）。每个文件的 `@BeforeEach` 各自构造 SUT 与桩，
  允许少量夹具重复，换来的是单文件职责单一、可独立阅读。
- **嵌套测试的 surefire 计数**：`@Nested` 内层用例计入外层类的 surefire XML，
  但 `mvn` 控制台输出的外层 `Tests run:` 可能显示 0——**统计用例数应以 surefire XML 为准**。
- **批量拆分用整文件重写而非脚本切片**：脚本按标记切分容易漏掉 import 与收尾大括号
  （本次踩过：漏 import 报「找不到符号」、漏 `}` 报「已到达文件结尾」）。
