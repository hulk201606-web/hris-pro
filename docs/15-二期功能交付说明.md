## 2. 工程实现方式

因限流窗口约束，采用「解析型代码生成器」保证与 DDL 零字段偏差、范式与考勤模块一致：

- 生成器：`scripts/gen_phase2.py`（纯标准库，读 DDL → 产出源码 + 修正骨架 pom/yml）
- 范式严格对齐考勤：实体继承 `com.hris.common.entity.BaseEntity`；mapper 继承 `BaseMapper`；
  service 用 `@Service` + 构造注入 + `@Transactional` + `R<T>`/`PageResult`；
  controller 用 `@RestController` + `@RequirePerm` + 统一前缀；DTO 用嵌套 `record`。
- 字段映射：DDL 蛇形列 → Java 驼峰字段（适配 `map-underscore-to-camel-case`），公共列
  （id/tenant_id/created_*/updated_*/deleted/version）由基类管理，不重复生成。
- 骨架 pom 补齐：`aspectj`（@RequirePerm 切面依赖）、`validation`、`openfeign`+`loadbalancer`、`actuator`。
- 网关路由已在 `hris-gateway` 配置（Path=/api/v1/{rcu,cmp,prf,kb}/**），无需改动。

## 13. 生成器类型白名单修复（2026-10-17）

### 13.1 根因
`scripts/gen_phase2.py` 的 `SQL2JAVA` 类型白名单缺 `MEDIUMTEXT`，导致 `kb_chunk.text` 列
（`MEDIUMTEXT` 类型）在解析时 `jtype=None` 被跳过，`Chunk` 实体/DTO/Service 均缺失 `text` 字段，
违反「零字段偏差」承诺。

### 13.2 修复
- `SQL2JAVA` 补齐：`MEDIUMTEXT→String`、`TIME→LocalTime`、`BLOB/LONGBLOB→byte[]`；
  `java_imports` 补 `LocalTime`。
- 影响面核验：`MEDIUMTEXT` 仅 kb_chunk.text（flow 的 bpmn_xml 为一期手写模块不在此范围）；
  `TIME` 仅 att_shift（手写模块已正确）；`BLOB` 仅 oauth2 表（一期）。
- 只重新生成 `Chunk` 实体 + `ChunkDtos` + `ChunkService` + `ChunkController`
  （复用生成器函数写临时脚本，避免整仓重跑覆盖手写 Feign/milvus 文件与 pom.xml）。

### 13.3 结果
`Chunk` 实体/DTO/Service 补上 `text` 字段（列序与 DDL 一致），编译 0 error、门禁通过。
`kb_chunk` 现完整支持 text 字段的 CRUD，为阶段 B embedding 输入就绪。

### 14.3 Embedding 接入（降级设计）
- `EmbeddingService`：注入 `ObjectProvider<EmbeddingModel>` + `OpenAiCommonProperties`，
  **以 api-key 是否为空**判定是否走真实 embedding（OpenAiEmbeddingModel bean 在缺 Key 时
  仍会被创建，不能以 bean 存在性判断）；无 Key 降级确定性占位向量，服务可启动、链路可验证。
- `IndexRebuildService`：chunk.text → EmbeddingService.embed → Milvus → milvus_id 回填。

### 14.4 修复的 runtime 缺陷（3 处，均实测发现）
1. **YAML 重复 `spring:` 键**：新增 `spring.ai` 块与原 `spring:` 并列导致启动失败

2. **Embedding 降级判错**：以 bean 存在性判断 → 无 Key 时仍调 API 报 401 →
  改为 api-key 判空。
3. **集合缺向量索引**：ensureCollection 只建集合不建索引，load/search 报
   `index not found (code=700)` → 补 `createVectorIndex`（describeIndex 幂等检查 +
   AUTOINDEX + COSINE），search 度量同步改 COSINE。
