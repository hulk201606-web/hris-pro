## 二、部署决策

1. **中间件**：Nacos + Redis + RocketMQ 全部 Docker 部署（用户要求 RocketMQ 也一起，为二期事件总线预留）。
2. **数据库**：本地 MySQL 8.4 执行完整 `schema-mysql.sql`（幂等 `CREATE ... IF NOT EXISTS`，10 库全建，一期用 5 个）。
3. **Flowable**：flow 服务首启临时开 `flowable.database-schema-update=true` 自动建 ACT_* 引擎表，建完关回 false。
4. **联调顺序**：先 gateway + auth 冒烟 → 打通后逐步起 org/employee/flow/platform。

## 三、执行步骤

### 步骤 1：初始化本地 MySQL
- 用 pymysql 逐条执行 `docs/db/schema-mysql.sql`（注意：DDL 是「多库 + 每库多表」结构，含 `USE` 切换，需按 `CREATE DATABASE` / `USE` 分片执行）。
- 验证：SHOW DATABASES 出现 auth_db/org_db/emp_db/flow_db/plt_db；抽查核心表（auth_user、org_dept、emp_employee、flow_ext_biz_relation、sys_audit_log）存在。

### 步骤 2：Docker 部署中间件
- 复用根目录 `docker-compose.yml`，但**移除 mysql/postgres** 服务（本地已有 MySQL），只起 nacos + redis + rocketmq（namesrv+broker）。
- 用 `docker compose up -d nacos redis rocketmq-namesrv rocketmq-broker` 指定服务。
- 健康检查：Nacos `http://localhost:8848/nacos/v1/console/health/readiness` 返回 UP；Redis `redis-cli ping` → PONG；RocketMQ namesrv 9876 端口监听。

### 步骤 3：冒烟 gateway + auth
- 启动 auth（配置指向本地 MySQL + Nacos + 临时注入 seed 数据用于登录测试）。
- 启动 gateway（端口 8080）。
- 冒烟用例：
  1. `GET /actuator/health` → 200（白名单放行）
  2. `GET /internal/auth/accounts` → 403 20403（内部封禁）
  3. `POST /api/v1/auth/login`（合法账号）→ 200 + access/refresh token
  4. `GET /api/v1/auth/me`（带 token）→ 200 + 用户信息；无 token → 401 20401

### 步骤 4：逐步起其余服务
- org → employee → flow → platform，每起一个做一次健康检查 + 关键端点冒烟。

## 四、风险与预案

| 风险 | 预案 |
|------|------|
| MySQL 8.4 与 DDL 的 `utf8mb4_0900_ai_ci` 兼容性 | 8.4 支持该排序规则；若报错改用 utf8mb4_unicode_ci |
| DDL 含 `USE` 语句 pymysql 需逐库执行 | 脚本按库切分执行，不一次 execute 全文件 |
| 无 seed 数据无法登录测试 | 手动插入最小测试租户/用户（Argon2id 密码需用 auth 服务同款编码生成，或用临时测试端点） |
| Nacos 3.1.1 镜像下载慢 | 已配置国内镜像源，重试或换 nacos/nacos-server:v2.4.3 |
| auth 服务启动依赖 Nacos 注册 | 确保 Nacos 先就绪再起服务 |
