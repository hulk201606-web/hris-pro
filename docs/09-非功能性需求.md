# 09 非功能性需求（NFR）

> 规模假设：单租户万人级、平台千租户、峰值并发 500+（审批）/5,000 TPS（打卡写入）。

## 1. 性能指标

| 编号 | 场景 | 指标 |
|---|---|---|
| NFR-P-001 | 花名册/待办列表查询 | P95 ≤ 300ms，P99 ≤ 800ms（10 万员工档案量级、常用筛选） |
| NFR-P-002 | 审批操作（含事件发布） | P95 ≤ 500ms |
| NFR-P-003 | 打卡写入洪峰 | 5,000 TPS 持续 15min 无丢失（网关→MQ→异步落库），端到端可见 ≤ 60s |
| NFR-P-004 | 月结计算 | 1 万人租户 ≤ 10min（分批并行、进度可查） |
| NFR-P-005 | 全量算薪 | 1 万人 ≤ 30min，试算（单人）≤ 3s |
| NFR-P-006 | RAG 问答 | 首 token ≤ 3s、完整答案 P95 ≤ 12s；检索段（召回+过滤+rerank）≤ 800ms |
| NFR-P-007 | 前端首屏 | 管理端 ≤ 2.5s（gzip 后路由分包、骨架屏） |
| NFR-P-008 | 报表导出 | 10 万行 ≤ 3min（异步任务+进度+下载链接） |

## 2. 可用性与容灾

| 编号 | 项 | 指标 |
|---|---|---|
| NFR-A-001 | 平台可用性 | 99.9%（月），核心链路（认证/待办/打卡）99.95% |
| NFR-A-002 | 部署 | K8s 双 AZ，服务 ≥2 副本反亲和；Nacos 3 节点、RocketMQ 主从+Controller、MySQL 一主两从（MHA/Orchestrator）、Redis Cluster 6 节点、Milvus 集群、ES 3 节点 |
| NFR-A-003 | RPO / RTO | ≤ 5min / ≤ 30min（数据库半同步复制 + 对象存储跨 AZ） |
| NFR-A-004 | 降级预案 | LLM 供应商故障→排队+兜底检索答案（列原文）；MQ 不可用→本地 outbox 阻塞重试；ES 故障→向量单路召回标注"精确度降级" |
| NFR-A-005 | 发布 | 蓝绿/金丝雀（网关权重），DB 变更向前兼容（expand-contract），回滚 ≤ 10min |

## 3. 扩展性

- 无状态服务水平 HPA（CPU/QPS/自定义 MQ 堆积指标）；打卡入口独立 Deployment 隔离洪峰。
- 分片可倍增扩容（06，扩缩容工具链与迁移窗口设计属实现期专项）。
- 租户存储模式升级通道：SHARED→DEDICATED 提供数据搬迁 runbook（设计锁定，实施脚本后期产出）。

## 4. 可观测性

- OpenTelemetry 全链路 trace（网关→服务→DB→MQ→模型调用），traceId 贯穿响应体与前端错误上报。
- 指标：RED（每端点）+ 业务水位（流程积压、outbox 延迟、月结任务、问答拒答率、模型 token 成本/租户）。
- 日志：结构化 JSON→Loki，敏感字段脱敏管道；审计日志独立存储通道（08）。
- 告警分级 P0（电话）/P1（IM）/P2（工单），SLO 错误预算月评审。

## 5. 容量与成本基线（万人租户/年）

业务库 ~80GB 热（含考勤打卡 300 万行/年归档后）、向量 ~50 万 chunk（1024 维，Milvus ~4GB）、
问答 100 万次/年（按 DashScope 计价设月度预算护栏 + 缓存命中率 ≥ 30% 目标）、模型调用成本按租户计量进账单（SaaS 计费预留）。

## 6. 兼容与约束

- 浏览器：Chrome/Edge 近两年版本；自助端移动 Web 360px+ 自适应。
- 数据保留：员工离职后档案按法规 ≥ 3 年（劳动合同），候选人简历默认 2 年可配（KBD/审计同理分级保留）。
- 国际化基座：时区/币种/双语框架就位（PLT-F-014），首期交付中文。

## 7. 验收测试口径

性能场景以上指标须通过压测报告验收：JMeter（工作区已有 5.6.3）脚本覆盖 NFR-P-001~006 主链路，
数据规模按 §5 生成；混沌项（NFR-A-004 各降级开关）纳入发布前演练清单。
