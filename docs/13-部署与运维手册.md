# 13 · 部署与运维手册（一期）

> 版本：v1.0　日期：2026-10-16　适用范围：一期 6 个服务（gateway / auth / org / employee / flow / platform）
> 本文是**把一期跑起来的唯一操作依据**。所有端口、环境变量、启动参数以本文和 `scripts/hris-env.sh` 为准，
> 若 `application.yml` 中的默认值与本文冲突，以本文为准（已在代码侧同步修正）。

## 3. 环境变量

唯一配置源：`scripts/hris-env.sh`。启动时由 `start-all.sh` 注入。

| 变量 | 必填 | 说明 |
|---|---|---|
| `JWT_SECRET` | 是 | HS256 密钥，≥32 字节；auth 与 gateway 必须同源；弱密钥拒绝启动（`JwtSecretGuard`） |
| `DB_PASSWORD` | 是 | 已移除代码内的硬编码默认值，缺失即启动失败 |
| `DB_HOST` / `DB_PORT` | 否 | 默认 `127.0.0.1` / `3306` |
| `DB_USERNAME` | 否 | 默认 `root` |
| `NACOS_ADDR` | 否 | 默认 `127.0.0.1:8848` |
| `MINIO_*` | 否 | 未就绪时 platform 文件服务降级为占位 URL + 日志 |

> 注意：曾踩坑：宿主若存在 `SERVER__PORT=7554`，Spring Boot relaxed binding 会把它解析成 `server.port`
> 并覆盖 yml。因此**所有服务必须用 `--server.port` 显式指定端口**（命令行参数优先级最高）。

## 4. 中间件启动

```bash
# 一期必需：Nacos + RocketMQ + Redis（这三个没有 profile，默认拉起）
docker compose up -d

# 可选（默认不拉起，避免抢占本机 3306）
docker compose --profile db up -d       # 容器内 MySQL / PostgreSQL
docker compose --profile storage up -d  # MinIO
docker compose --profile rag up -d      # ES + etcd + Milvus（二期）
```

> `mysql` / `postgres` 已加 `profiles: [db]`：本机已有 MySQL 8.4 时若直接 `docker compose up -d`
> 会与本机实例抢 3306 端口。

## 5. 数据库初始化

```bash
python scripts/init_db.py          # 执行 docs/db/schema-mysql.sql，建 5 个库并校验核心表
python scripts/seed_e2e.py         # 灌组织/员工 seed（法人 300001、部门 300002、岗位 300003、员工 200001）
```

说明：`scripts/seed_auth_admin_rbac.sql` 使用了 `SET @tenant_id := 100001;` 会话变量，
**不能被"按分号切分后逐条执行"的脚本驱动**（Python 直连执行会得到 0 行）。
改用参数化 SQL 逐条插入，或直接连接 MySQL 客户端执行整个文件。

## 6. 服务启停与巡检

```bash
export JWT_SECRET='<≥32字节强密钥>'
export DB_PASSWORD='<本机 MySQL 口令>'

bash scripts/start-all.sh           # 用已有 jar 启动，并轮询 /actuator/health/liveness
bash scripts/start-all.sh --build   # 先 mvn package 再启动
bash scripts/status-all.sh          # 服务 + 中间件状态巡检
bash scripts/stop-all.sh            # 按 PID 文件精确停止
```

日志目录默认 `/tmp/hris-logs`（可用 `HRIS_LOG_DIR` 覆盖）。

## 7. 在 IDE / Agent 的 Bash 工具里启动

`start-all.sh` 用 `nohup ... &` 拉起子进程；在某些托管会话中，子进程会随 shell 退出被回收。
那种场景改用「**前台 java + 后台任务**」逐个拉起（这也是本仓库联调时实际使用的方式）：

```bash
"D:/Program Files/Java/jdk-21.0.12.1/bin/java" \
  -jar hris-auth/target/hris-auth-1.0.0-SNAPSHOT.jar \
  --server.port=8101 \
  --spring.datasource.url="jdbc:mysql://127.0.0.1:3306/auth_db?useUnicode=true&characterEncoding=UTF-8&serverTimezone=UTC" \
  --spring.datasource.username=root --spring.datasource.password="$DB_PASSWORD" \
  --auth.jwt.secret="$JWT_SECRET"
```

网关额外需要 `--hris.jwt.secret="$JWT_SECRET"`（网关配置前缀是 `hris.jwt`，与 auth 的 `auth.jwt` 不同）。

## 8. 健康检查

每个服务都暴露（含 gateway）：

- `GET /actuator/health/liveness`
- `GET /actuator/health/readiness`
- 仅暴露 `health,info`；`show-details: never`，不泄漏 `env` / `beans` / `heapdump`

> 一期初版只有 gateway 引了 actuator，5 个业务服务没有——`/actuator/health` 落到全局兜底
> 异常处理器返回 50001，K8s 就绪探针会直接判死。已为 5 个服务补齐依赖与 `management` 配置。

## 10. 已知坑（联调实录）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | Nacos 启动退出 255 | v3.x 强制要求 `NACOS_AUTH_TOKEN`，且原文 ≥32 字节 | 配 Base64 token（62 字节原文，无尾换行） |
| 2 | RocketMQ broker 退出，报 `ScheduleMessageService.configFilePath` NPE | 次要错误；真因是 named volume 属主为 root，容器内以 uid 3000 运行导致 store 不可写 | broker 加 `user: root` |
| 3 | broker 配置不生效 | 镜像内路径是 `/home/rocketmq/rocketmq-5.3.1/conf` 而非 `/home/rocketmq/conf` | 修正挂载路径 + `NODE_ROLE=broker` + `command ["-c","../conf/broker.conf"]` |
| 4 | 网关所有路由 404 / 500 | Spring Cloud Gateway 5.x 配置根迁移：`gateway.routes` → `gateway.server.webflux.routes`，旧键静默失效 | 迁移配置根 |
| 5 | 启动报 `BeanDefinitionOverrideException: gatewayProperties` | 自建类 `GatewayProperties` 与框架内置 bean 同名 | 改名为 `HrisGatewayProperties` |
| 6 | `/internal/**` 公网可穿透 | 用 GlobalFilter 实现，无路由匹配时不执行 | 改 `WebFilter`（order -700），在路由匹配前拦截 |
| 7 | 登录报 `Unsupported character encoding 'utf8mb4'` | MySQL Connector/J 9.x 不接受 `utf8mb4` | 全量改为 `characterEncoding=UTF-8` |
| 8 | Feign 调用 `No qualifying bean of type LoadBalancerClient` | OpenFeign 5 不再内置负载均衡 | 显式引入 `spring-cloud-starter-loadbalancer` |
| 9 | 服务端口与预期不符 | 环境变量 `SERVER__PORT` 被 relaxed binding 解析为 `server.port` | 一律 `--server.port` 显式覆盖 |
| 10 | jar 打包失败 "Unable to rename jar" | 旧进程占用 | 先 `stop-all.sh` 再 `package` |
| 11 | `setsid: command not found` | Git Bash for Windows 无 setsid | 改用 `nohup ... &` |

## 11. 生产化待办（一期未覆盖）

- `JWT_SECRET` / `DB_PASSWORD` 改为 KMS 或 K8s Secret 注入，禁止出现在 shell history
- 敏感字段（身份证、银行卡、手机号）目前明文存储，需 KMS 信封加密（见 §P1 缺陷清单）
- JWT 黑名单/刷新令牌目前走 JVM 内存 `refreshStore`，多实例下失效，需迁 Redis
- 缺少集中日志与链路追踪采集（traceId 已有，未接采集端）
- 缺 Dockerfile / K8s manifest（当前仅 jar + compose 中间件）
