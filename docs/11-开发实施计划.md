## 2. 开发总原则与铁律

以下原则凌驾于所有任务包之上，任何一期、任何服务的产出都必须通过，逐期门禁中强制检查。

### 2.1 三条 P0 绝对规则

| # | 规则 | 落到开发的动作 |
|---|---|---|
| P0-1 | 禁止 emoji 作功能图标 | 全项目锁定**一套** SVG 图标库，尺寸 16/20/24px；前端代码门禁用 emoji 正则全量扫描 .tsx/.vue/.html |
| P0-2 | 禁止紫色→粉色渐变主视觉 | 禁止 `#7C3AED→#A855F7→#EC4899` 及 Indigo→Pink 任意渐变组合 |
| P0-3 | 禁止 AI 模板味代码/文案 | 禁止 Lorem ipsum/空洞占位；禁止硬编码颜色值（例外 `#fff`/`#000`）；禁止弹跳缓动 `cubic-bezier(0.68,-0.55,0.265,1.55)` |

### 2.2 技术栈锁定（禁止越权改选型）

技术选型以《02 系统架构设计》版本矩阵为准，开发中**不得擅自替换框架/库/版本**。关键锁定：

- JDK 21 LTS（虚拟线程）；Spring Boot **4.0.x（不用 4.1）**；Spring Cloud 2025.1.x；SCA 2025.1.0.0
- Flowable 7.2.x（BPMN+DMN）；Spring AI Alibaba + Milvus 2.5.x
- MySQL 8.0.x + ShardingSphere-JDBC 5.4.x+；Redis 7.x；MinIO；MyBatis-Plus Boot4 适配版
- Vue 3.5+ / Vite 7 / TS 5 / Pinia / Vue Router 4 / Ant Design Vue 4.x / bpmn-js 17.x / ECharts 5.x

### 2.3 代码组织纪律（后端）

- 分层：`controller → service → repository/mapper`，依赖只向下，禁止逆向依赖
- 单文件 ≤ 300 行；入口文件（Application/装配类）只做装配，零业务逻辑
- 单一职责；业务逻辑下沉 service，controller 只做参数校验与协议转换
- 统一响应体 `{code, message, data, traceId, timestamp}`（见 07）

### 2.4 越权零容忍（贯穿所有迭代）

四层纵深隔离（网关→服务→ORM→存储，见 08 §3），且**每个迭代必跑越权测试矩阵**：
水平越权（同角色跨员工/部门）、垂直越权（低角色打高权限端点）、跨租户探测（篡改 tenant 参数/头）、
内部路径外打（/internal/** 经公网必须封禁）。

## 5. 开发依赖拓扑与实施顺序

服务间存在硬依赖，实施顺序必须遵循（先横向底座，再核心人事，再业务域，最后 AI/深化）：

```
第一层 工程底座:  父工程/版本矩阵 → Docker Compose → 公共 starter/审计/错误码
第二层 横向支撑:  gateway → auth → platform(文件/通知/字典/审计/调度)
第三层 核心人事:  org → employee ──► flow(引擎装配+6模板)
第四层 业务域:    attendance → recruit ──► compensation → performance
第五层 AI 深化:  rag ──► 个性化口径/开放API/报表中心
```

**关键先行验证（第 1 周硬门禁）**：Flowable 7.2.x 官方基于 Boot 3.x 验证，本项目基线 Boot 4.0.x，
**实现第一阶段必须做引擎装配验证**（04 §8），验证清单与降级预案：

| 验证项 | 通过标准 | 失败降级 |
|---|---|---|
| flowable-spring-boot-starter-process 在 Boot4 自动配置可用 | 引擎可装配并跑通最小 BPMN 实例 | 预案 A：自建 @Configuration 手工装配 ProcessEngineConfigurationImpl |
| Jackson 2→3 迁移对 Flowable 序列化影响 | 流程变量持久化/反序列化正常 | 预案 B：hris-flow 单服务锁 Boot 3.5.x |
| 事务管理器与 Spring 6.2/7 语义兼容 | @Transactional 语义正确 | 预案 C：升级 Flowable 对 Boot4 适配版后回填版本矩阵 |

> 该验证项若第 1 周未通过，**整期冻结**，先定降级方案再继续，避免后期返工。
