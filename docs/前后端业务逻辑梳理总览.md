# 智云 HR 多租户 SaaS 系统 —— 前后端业务逻辑梳理总览

> 生成日期：2026-10-19
> 范围：12 个后端微服务（共 645 个 Java 主代码文件）+ 1 个前端 SPA（35 个 .vue + 23 个 .ts）
> 配套文档：`docs/shard-a-业务梳理.md`（基础设施层）、`shard-b`（人事主数据域）、`shard-c`（考勤薪酬绩效域）、`shard-d`（流程/AI/平台/前端）

---

## 一、系统定位

智云 HR 是一套面向多租户的 SaaS 化 HR 平台，覆盖从组织主数据、员工全生命周期、招聘、考勤、薪酬、绩效，到流程审批中台、AI 知识库问答与平台基础服务的完整 HRIS 能力。技术栈为 Spring Boot 4.0 + Spring Cloud 2025 + Spring Cloud Alibaba + MyBatis-Plus + Flowable 8 + Spring AI + Nacos + RocketMQ + MySQL/PostgreSQL + Redis + Milvus；前端为 Vue 3 + TypeScript + Vite + Ant Design Vue 4 + Pinia 的单 SPA（员工自助端 `/self` 与管理端 `/admin` 双端合一）。

## 三、端到端业务主线

### 主线 1：招聘 → 入职 → 算薪 的完整员工价值链

```
hris-recruit                hris-employee              hris-org
招聘需求 → 职位发布           预建档(PENDING)             编制校验
候选人入库                   入职办理                    编制占用回写
  │                          │ 编制校验
  │                          ▼
  │                      EMP_ONBOARD 流程（hris-flow）
  │                          │
  │                          ▼
  └── Offer 接受 ──────► 员工状态 PENDING→PROBATION→ACTIVE
                              │
                              ├── 转正（EMP_REGULAR）
                              ├── 调动（EMP_TRANSFER，目标编制校验）
                              └── 离职（EMP_RESIGN）
```

- 招聘域 `OfferOnboardService.acceptAndOnboard` 通过 EmployeeClient 调 employee `/internal/emp/pre-create` 预建档，幂等置 `offer=ACCEPTED`、`candidate=HIRED`。
- 员工域 `OnboardingService` 调用 `HeadcountIntegration` 校验编制，发起 `EMP_ONBOARD` 流程，完成后创建默认账号（AuthClient）。
- 员工状态机为八态：PENDING / PROBATION / ACTIVE / RESIGNING / RESIGNED / CANCELLED / RETIRED / BLACKLISTED，所有流转由 `EmployeeStateMachine` 统一校验并落状态流水。

### 主线 2：考勤 → 薪酬 → 绩效 的月度运营闭环

```
员工打卡 ─► PunchService ─► DailyAttendanceService（日结幂等 upsert）
                              │ 迟到/早退/旷工/缺卡规则判定
                              ▼
请假/加班/补卡/出差审批 ──► hris-flow 流程引擎 ──► ApprovalService 回写
                              │
                              ▼
                  MonthlyClosingService 月结锁账（INIT→RUNNING→DONE）
                              │
                              ▼ Feign 取月结汇总
                  PayrollRunService（DRAFT→CALCULATING→LOCKED→PAID→ARCHIVED）
                              │ 组合员工主档 + 考勤结果
                              ▼
                  SalarySecretService（密域 cipher/mask 双列，需 cmp:salary:read）
                              │
                              ▼
                  PayslipService 工资单生成 ──► PaymentInstructionService 银行发放指令

绩效域：绩效周期 → OKR 目标 → 自评 → 上级评 → 校准 → 强制分布 → 评级归档
                └──► 绩效系数回写薪酬算薪项（跨域联动）
```

### 主线 3：登录与多租户鉴权链路

```
浏览器
  │
  ▼
hris-gateway（WebFlux）
  TraceIdGlobalFilter(-1000) → InternalBanWebFilter → RequestSizeGuard(-850)
  → Whitelist(-800) → JwtAuth(-600) → AccessLog(-900)
  │  验签后丢弃客户端伪造头，注入 X-User-Id / X-Tenant-Id / X-User-Roles / X-User-Perms
  ▼
下游业务服务（Servlet）
  TraceIdFilter → AuthContextFilter → PermAspect（@RequirePerm 校验）
  │
  ▼
MyBatis-Plus TenantLineInnerInterceptor 自动在 SQL 追加 tenant_id 条件
```

- 登录入口在 `hris-auth`：AuthService.login → TokenService 签发 access(15min) + refresh(7d)，MFA 走 TOTP。
- 内部端点（`/internal/**`）由网关 `InternalBanWebFilter` 一律 403，仅服务间 Feign 调用可达。
- RBAC 三级同源：菜单树由权限点 `模块:资源:动作` 切分派生；数据权限支持 SELF / DEPT / DEPT_SUB / CUSTOM / ALL。

### 主线 4：流程中台复用（hris-flow）

hris-flow 不绑定具体业务，而是为所有需要审批的业务单提供统一能力：

- `ModelService` 部署 BPMN XML → `InstanceService` 按 bizType + bizKey 发起实例（幂等）→ `AssigneeResolver` 解析审批人（指定人 → 汇报线 → 角色）→ `TaskActionService` 处理 approve/reject/transfer/add_sign/withdraw。
- `BizRelation` 表维护业务单 ↔ 流程实例映射；`EventOutbox` 以事务消息兜底事件发布，由 `ReconcileService` 定时重投未消费消息。
- 请假、加班、补卡、出差、入职、转正、调动、离职、组织调整等业务单均通过 FlowClient 接入，审批完成后经 `FlowInternalController` 回调业务模块回写状态。

### 主线 5：RAG 知识库问答链路

```
文档上传（MinIO 预签名直传，hris-platform）
  → hris-rag DocumentController 落元数据 + 指纹
  → ChunkService 切片 → Embedding 向量化
  → 写入 Milvus 集合（按 tenant 隔离）
  → ACL 标签 / 知识空间 控制可见范围
  → 语义检索召回 Chunk → 拼装 Prompt → 大模型生成答案
  → EvalSet/EvalRun 沉淀评测用例与命中率
  → GovernTicket 处理低质/过期知识
```

## 四、横切能力（hris-common 提供）

| 能力 | 实现类 | 说明 |
|------|--------|------|
| 统一响应体 | `api.R` | `{code, message, data, traceId, timestamp}`，所有 Controller 返回值统一包装 |
| 业务异常 | `exception.BizException` + `ErrorCode` | 错误码分段：1xxxx 通用 / 2xxxx 认证授权 / 3xxxx 流程 / 4xxxx RAG / 5xxxx 业务域 |
| 全局异常 | `GlobalExceptionHandler` | Servlet 侧兜底，转 R.fail；另有 404 / 参数校验专项 handler |
| 租户隔离 | `mybatis.MybatisPlusConfig` | TenantLineInnerInterceptor 自动追加 tenant_id；`@InterceptorIgnore` 用于平台级表（如 AuthTenant） |
| 权限切面 | `security.PermAspect` + `RequirePerm` | 拦截 `@RequirePerm("模块:资源:动作")`，缺失抛 20403 |
| 权限上下文 | `security.AuthContextFilter` + `AuthContextHolder` | 从网关透传头还原 userId/tenantId/perms/roles |
| 审计埋点 | `audit.AuditLogAspect` | 环绕 `@AuditLog` 方法，输出结构化审计日志 |
| 链路追踪 | `trace.TraceIdFilter` + `TraceContext` | traceId / tenantId / userId 贯穿请求→DB→MQ |
| JWT 安全 | `security.JwtSecretGuard` | 启动期强校验密钥，拒绝空值/弱密钥/默认值 |

- 项目 `pom.xml` 要求 Java 21，本机默认 `JAVA_HOME` 指向 JDK 17 不兼容。
- 各 shard 统一改用本机 JDK 25（`D:\Program Files\Java\jdk-25.0.4.1`）执行 `--release 21` 编译，或临时 `-Djava.version=17` 覆盖（仅注释变更，无语法特性依赖）。

## 六、关键业务规则速查

| 业务点 | 规则 |
|--------|------|
| 员工状态机 | 八态（PENDING/PROBATION/ACTIVE/RESIGNING/RESIGNED/CANCELLED/RETIRED/BLACKLISTED），由 EmployeeStateMachine 统一校验 |
| 算薪批次状态 | DRAFT → CALCULATING → LOCKED → PAID → ARCHIVED；LOCKED 后不可改 |
| 月结状态 | INIT → RUNNING → DONE / FAILED；月结锁账后考勤结果冻结 |
| 流程实例状态 | RUNNING / FINISHED / TERMINATED |
| 审批动作 | APPROVE / REJECT / TRANSFER / ADD_SIGN / WITHDRAW |
| 数据权限范围 | SELF / DEPT / DEPT_SUB / CUSTOM / ALL |
| JWT TTL | access 15min / refresh 7d |
| 薪酬密域 | cipher（密文）+ mask（掩码）双列；读取需 `cmp:salary:read` 权限 |
| 内部端点 | `/internal/**` 网关一律 403，仅 Feign 服务间可达 |
| 编制校验 | 部门 × 岗位 × 季度三元组；入职/调动前必须通过 |
